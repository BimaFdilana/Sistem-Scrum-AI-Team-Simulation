# Stage 2 — Agent model configuration (source-only)

## Website boundary

The authenticated Agent page offers **one model selector** per role (Scrum Master, Frontend, Backend, QA). Each option encodes a provider/model pair from that role's authenticated live catalog; the provider is derived server-side from the selected option. There is no website editor for instructions, SOUL, skills, profile, policy, credentials, endpoint or provider separately. The update and restore endpoints reject all such submitted fields. No model is preselected from a local default; an unavailable/offline catalog cannot authorize a save, even of an unchanged model or a restore. A model must be available in the role's live catalog at save time. Different roles cannot activate the same model ID. Saving uses optimistic versions and append-only audit records.

Routes: `GET /agents/{slug}/config`, `PUT /agents/{slug}/config`, `GET /agents/{slug}/config/history`, `POST /agents/{slug}/config/restore/{version}`, and `GET /agents/{slug}/config/connectivity`. Web writes require authentication and CSRF. History HTML/JSON exposes only actor/time/version/status/provider/model metadata; it never returns persona or skill text. A restore creates a new version with the old model selection, revalidated against today's catalog, and the current fixed packaged role content (not prior editable text).

## Fixed role content for configured consultation

`resources/agents/role-packs.json` packages a read-only copy of the four current native Hermes `SOUL.md` files and each role's curated `SKILL.md`. Both `instructions` and `soul` snapshot columns contain that role's full SOUL content; `skill_snapshot` contains its full selected native SKILL.md body plus SHA-256. This duplicates SOUL in the request payload, but avoids silently using older short role-pack text. No browser input can change these fields. Native files are **not** read or written by the Laravel runtime: updating native persona/skills later requires explicitly refreshing this source copy and deploying a new application version; existing saved snapshots remain immutable. The common policy is also immutable and overrides persona/skill text.

The currently configured Hermes API toolsets are empty; native skill autoload is not assumed. For configured consultation only, a snapshot's packaged skill body is therefore embedded in the native session `system_message`. A verified provider/model is locked on session creation and chat (`require_model_lock: true`); the version-specific session ID pins existing conversations. Response acceptance requires actual served provider/model metadata from native session chat, never an LLM claim or request echo. Missing/mismatched metadata fails closed and is audited. This is consultation only; code execution remains disabled. Gateways can retain prior cached native SOUL until their sessions/restarts refresh; this source change does not restart gateways or prove live inference.
